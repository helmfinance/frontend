A. 컨트랙트 재배포 후 프론트엔드 주소록(addresses.json) 이 통째로 어긋남

컨트랙트를 다시 배포할 때마다 모든 컨트랙트 주소가 새로 생기는데, 프론트엔드가 들고 있는 주소록이 이전 배포의 것으로 남아 있었습니다. 백엔드는 새 주소로 갱신돼 있어서 — 백엔드를 거치는 화면(마켓플레이스, 포트폴리오 등)은 멀쩡해 보이지만, 프론트엔드가 체인에 직접 거는 동작 (민트, 시간 가속 시계 표시 등)은 모두 존재하지 않거나 다른 컨트랙트를 가리켜서 조용히 실패합니다.

관찰된 상태

프론트엔드 addresses.json 과 백엔드 GET /system/info 의 주소를 전수 비교한 결과, 13개 컨트랙트 + 5개 합성자산 전부 불일치였습니다. 예시:

컨트랙트FE (구 배포)BE (현 배포)
registry0x9add2f9f…0x120CADfa…
usdc0x903c727D…0xd5a92Cf8…
timeProvider0x908E9154…0xce2aE0a3…
sNVDA0x985CfD43…0xa3beDd97…

프론트엔드 영향

  • 체인에 직접 거는 모든 트랜잭션(민트, 환매, founder 액션, 에이전트 등록)이 존재하지 않는/잘못된 컨트랙트를 호출해서 실패.
  • 어드민 "시간 가속" 카드가 잘못된 TimeProvider 의 시계를 읽어서, 백엔드가 실제로 advance 하는 시계와 한 달 가까이 차이나는 값을 표시.

프론트엔드 측 조치 (완료)

GET /system/info 를 기준으로 addresses.json 을 전면 교체했습니다. ABI 는 재배포 전후로 동일해서 그대로 사용 가능했습니다.

백엔드 측 요청

재배포할 때 프론트엔드도 같은 주소록을 받을 수 있도록, 새 주소 세트를 한곳(예: frontend-package/addresses.json)에서 항상 최신으로 유지해 주시면 좋겠습니다. 지금은 재배포 사실을 프론트엔드가 알 방법이 없어 매번 직접 /system/info 와 대조해야 합니다.

open high

B. POST /admin/time/advance 가 큰 점프(예: +30일)를 실제로 반영하지 않음

어드민 화면의 시간 가속(+30일 등)을 호출하면 백엔드는 정상(200)으로 응답하지만 체인의 시계가 실제로는 거의 움직이지 않습니다. 작은 점프 (+2일)는 동작하는 것으로 보이는데 큰 점프는 반영이 안 돼서, 데모에서 인큐베이션 30일을 빠르게 건너뛰는 시나리오가 막힙니다.

관찰된 상태

+30일(2592000초) 을 요청했을 때 응답과 실제 체인 시계가 서로 맞지 않았습니다. 

요청:   POST /admin/time/advance  { "seconds": 2592000 }
응답:   200  { "advancedSeconds": 2592000, "newCurrentTime": 1782871045 }

호출 전 on-chain currentTime: 1787968641
호출 후 on-chain currentTime: 1787968649   ← +8초 (실제 경과시간만)

응답이 알려준 newCurrentTime(1782871045) 은 호출 전 실제 시계(1787968641)보다 오히려 과거이고, 호출 후 체인 시계는 30일이 아니라 8초만 움직였습니다. 즉 advance 가 누적되지 않거나 큰 값에서 적용되지 않는 것으로 보입니다.

프론트엔드 영향

  • 어드민의 "Demo bootstrap" 마지막 단계에서 인큐베이션 일수를 30일 이상으로 끌어올리지 못합니다. (운용 결정/NAV 누적 등 다른 자격 기준은 이미 정상 충족되는 것을 확인 — rebalance 수정 덕분.)
  • 실제로 큰 점프가 동작했다면 자격 6개 기준이 모두 통과하면서 인큐베이션 → 공개 운영 전환 데모가 완결됩니다. 현재는 이 시간 점프만 막혀 있습니다.

백엔드 측 요청

  • TimeProvider 의 advance 가 누적 오프셋으로 적용되는지, 한 번에 더할 수 있는 상한이 있는지 확인 부탁드립니다.
  • 응답의 newCurrentTime 이 실제 on-chain currentTime() 과 일치하도록 맞춰주시면 프론트엔드가 가속 결과를 신뢰하고 표시할 수 있습니다.
